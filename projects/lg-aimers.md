# LG Aimers — 투구별 제구 확률 예측

**Domain Understanding · Hypothesis-driven Modeling · Tabular ML**

경기 상황과 선수의 과거 이력을 바탕으로, 공을 던지기 전에 제구 결과의 확률을 예측한 팀 프로젝트입니다.
예선과 본선에서 타깃과 평가 방식이 달라졌고, 각 단계에 맞춰 데이터 해석·모델 구조·검증 방법을 다시 구성했습니다.

이 프로젝트에서 저는 **성능이 막히는 이유를 정보, 표현 방식, 데이터의 의미, 비교 조건으로 나누고 검증하는 것**에 집중했습니다.
새로운 모델을 시도할 때도 어떤 가설을 확인하려는지, 기존 구성에서 무엇이 달라지는지부터 정리했습니다.

## 결과

| 단계 | 과제 | 팀 성적 |
| --- | --- | --- |
| 예선 | 투구별 제구 성공 확률 예측 | **24위 · 본선 진출** |
| 본선 | Shadow·Heart·Failure 3등급 확률 예측 | **17위** |

예선은 확률 오차를 평가하는 Brier Skill Score 기반 과제였습니다.
본선에서는 **투구별 확률 정확도(Pitch, 70%)와 투수별 제구 순위(Player, 30%)**를 함께 평가했습니다.
이 변화는 투구 하나를 잘 예측하는 문제와 선수 간 수준 차이를 보존하는 문제를 나누어 보는 계기가 됐습니다.

## 제가 문제를 풀어간 프레임

| 먼저 던진 질문 | 실제로 확인한 것 | 이어진 판단 |
| --- | --- | --- |
| 부족한 것은 정보인가, 정보를 사용하는 방식인가? | 기존 피처의 재표현, FTT의 토큰화·깊이, 잔차 예측 가능성 비교 | 피처 추가와 모델 구조 변경을 서로 다른 가설로 다룸 |

## 1. 성능의 병목을 정보와 표현으로 나누기

예선에서는 선수 이력과 경기 상황을 여러 형태로 피처화했습니다.
이 과정에서 **새 피처가 추가 정보를 주는지, 이미 있는 정보를 다른 모양으로 표현한 것인지**를 구분했습니다.
피처 수가 늘어나도 같은 정보를 반복한다면 개선이 제한될 수 있다고 보고, 입력 정보와 모델 구조를 각각 점검했습니다.

FT-Transformer에서는 수치 피처를 의미별 블록으로 묶는 방식과 피처별로 토큰화하는 방식, 모델 깊이를 바꾸어 실험했습니다.
같은 입력 정보를 모델이 어떻게 결합하는지 바꾸면서 예측과 기존 모델과의 관계가 달라지는지 확인했습니다.
반대로 특정 선수 구간의 남은 오차는 간단한 잔차 모델로 회수 가능한지 살펴보고, 현재 입력으로 개선하기 어려운 후보는 우선순위를 낮췄습니다.

**판단의 기준은 “더 복잡한가”보다 “현재 병목을 바꾸는가”였습니다.**
이 구분을 통해 추가 피처, 새로운 모델 계열, 기존 모델의 용량 확대에 각각 다른 실험 목적을 부여했습니다.

## 2. 모델의 가치를 전체 구성 안에서 판단하기

예선 실험에서는 단독 점수의 순서와 앙상블에서의 기여 순서가 달랐습니다.
FTT가 단독으로 가장 좋은 모델이 아닌 비교에서도, 제거했을 때 전체 성능의 손실이 크게 나타났습니다.
이를 계기로 모델의 정확도와 함께 **기존 모델과 어디에서 다르게 예측하는지**를 분석했습니다.

비교는 세 가지로 나눴습니다.

- **추가:** 기존 구성을 유지하고 새 모델을 더했을 때 무엇이 개선되는가.
- **제거:** 특정 모델을 뺐을 때 전체 구성이 잃는 정보는 무엇인가.
- **대체:** 비슷한 역할의 모델을 바꾸었을 때 정확도·다양성·추론 비용이 어떻게 달라지는가.

새 모델의 비중을 확보하면서 기존 모델들을 일괄적으로 줄인 실험에서는, 새 모델의 효과와 기존 구성의 비중 감소 효과가 섞였습니다.
이후에는 가중 이동과 모델 교체를 나누어 비교했습니다.
또한 예측 상관이 낮다는 조건만으로 후보를 채택하지 않고, 단독 성능과 현재 앙상블에 더했을 때의 개선을 함께 확인했습니다.

**좋은 부품의 목록을 만드는 것과 좋은 조합을 만드는 것은 서로 다른 최적화 문제**라는 관점으로 실험을 진행했습니다.

## 3. 데이터가 만들어지는 구조를 모델에 반영하기

### 투수의 기본 수준과 경기 상황을 분리

본선에서는 투구별 확률 오차와 투수별 순위가 함께 중요했습니다.
일부 모델은 선수 이력과 상황 정보를 섞으면서 투수 간 예측 차이를 평균 쪽으로 압축하는 양상을 보였습니다.
투구 단위 점수만으로는 이런 변화를 설명하기 어려워, 투수별 평균 예측·과거 이력과의 관계·순위 변화를 따로 진단했습니다.

이에 투수의 과거 등급 분포에서 기준 로짓을 만들고, 모델이 상황에 따른 조정을 학습하는 구조를 검토했습니다.
이력이 적은 선수의 기준값은 전체 분포 쪽으로 보정했습니다.
팀원의 FTT를 바탕으로 로짓에 이 기준값을 더하는 **margin FTT**를 구성해, 투수 수준과 상황 효과를 분리해 학습하도록 유도했습니다.

```text
과거 선수 이력 → 등급 분포 보정 → 투수 수준의 기준 로짓
경기 상황·선수 피처 → 모델이 학습하는 조정 로짓
기준 로짓 + 조정 로짓 → softmax → 3등급 확률
```

이는 margin FTT의 핵심 구조를 요약한 것으로, 본선 팀 모델에는 트리 모델과 팀원들의 보정·결합 로직도 함께 사용했습니다.

### 리그별 기록의 의미를 확인

1군과 퓨처스의 데이터를 비교할 때는 같은 선수와 같은 컬럼이라도 기록 체계에 따라 제구 결과의 의미가 달라질 수 있다는 점을 확인했습니다.
특히 반대투구 기록 여부가 다른 데이터를 한꺼번에 사용하면, 경기 상황과 제구 결과의 관계를 잘못 학습할 가능성이 있었습니다.

그래서 **과거 이력을 합치는 기준과 상황별 보정을 학습하는 기준을 따로 검토**했습니다.
카운트 기반 보정에서는 1군에 적용할 관계를 1군 기록으로 다시 적합하고, 퓨처스에 적용하는 방식과 구분해 평가했습니다.
데이터를 더 모으는 선택뿐 아니라, 어떤 관계를 학습할 때 같은 의미의 표본을 묶어야 하는지도 판단했습니다.

## 4. 실험 결과가 엇갈리면 비교의 전제를 다시 보기

검증에서 좋아진 변경이 실제 제출에서 유지되지 않는 경우가 있었습니다.
그때 모델 자체와 함께 **검증 모델과 제출 모델의 차이**를 되짚었습니다.

| 확인한 문제 | 이후 실험에서 바꾼 점 |
| --- | --- |
| 검증 모델과 제출 모델의 학습 연도·시드 수가 다름 | 기준 모델의 구성과 학습 조건을 맞추어 비교 |
| 과거 검증 모델에 맞춘 보정값이 제출 모델에는 다른 효과를 냄 | 모델 출력의 수준 변화와 보정 효과를 나누어 점검 |
| 모델 교체와 가중 변경을 동시에 수행함 | 변경 효과를 분해하고 가능한 한 한 번에 한 가설을 비교 |
| 작은 점수 차이가 시드 조합에 따라 달라짐 | 반복 실행의 변동을 확인하고 후보를 재평가 |
| 특정 연도의 개선이 다른 연도로 이어지지 않음 | 여러 시간 구간을 비교하고 변경 유형별로 결과를 해석 |

단일 검증 점수를 모든 실험의 공통 판단 기준으로 쓰기보다, 모델 계열 변경·보정값 변경·가중 재배분이 각각 어떤 조건을 검증해야 하는지 구분했습니다.
이 판단 기준도 기존 실험을 돌아보며 수정한 것이므로, 새로운 후보에 대한 확신과는 구분했습니다.

추론 단계에서는 동일한 투구를 단독으로 넣거나 입력 순서·부분집합을 바꾸어도 예측이 유지되는지 확인했습니다.
행 독립성, 확률 범위와 합, 저장·추론 일치, 제출 환경의 실행 조건을 점검하는 작업에도 참여했습니다.

## 이 경험에서 드러난 문제 해결 방식

저는 성능 문제를 만나면 **무엇을 알고 있는지, 무엇이 섞여 있는지, 지금 무엇과 비교하고 있는지**부터 나누어 봅니다.
LG Aimers에서는 이 질문을 선수의 기본 수준과 상황의 분리, 기록 체계의 해석, 모델 간 역할 비교, 검증 조건의 재점검으로 구체화했습니다.
도메인 지식을 익혀 모델에 반영하고, 설명과 실험 결과가 어긋날 때는 처음의 가설과 판단 기준도 수정하는 방식으로 과제를 수행했습니다.

대회 데이터·선수별 원기록·모델 가중치와 팀 코드는 비공개로 유지합니다.
