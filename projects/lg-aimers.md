# LG Aimers — 투구별 제구 확률 예측

경기 상황과 선수의 과거 이력으로, 공을 던지기 전에 제구 결과의 확률을 예측한 팀 프로젝트입니다.
예선과 본선의 타깃·평가 기준 변화에 맞춰 피처, 모델 구조와 검증 방법을 재구성했습니다.

## 과제와 팀 결과

- **예선 24위 · 본선 진출** — 투구별 제구 성공 확률 예측.
- **본선 17위** — Shadow·Heart·Failure 3등급 확률 예측.

예선은 Brier Skill Score 기반 과제였습니다.
본선은 투구별 확률 정확도(Pitch, 70%)와 투수별 제구 순위(Player, 30%)를 함께 평가해,
투구의 상황 효과와 선수 간 수준 차이를 나누어 살펴봤습니다.

## 개인 역할

- 선수 이력·경기 맥락·리그별 기록 체계를 분석하고 피처와 실험 가설을 구성했습니다.
- FTT의 토큰화·깊이·시드, 트리·신경망 조합, 오프셋 모델과 margin FTT를 실험했습니다.
- 단독 성능과 앙상블 기여를 비교하고, 검증 조건·추론 동작·제출 패키지를 점검했습니다. 채택·기각 근거는 팀 실험 기록으로 공유했습니다.

## 주요 실험

### 1. 유지되는 관계와 변하는 관계, 정보와 표현을 구분

좌우 매치업·카운트·이닝·월·경력 구간의 효과를 연도별로 비교했습니다.
같은 해의 잔차 패턴이 다음 해에도 이어지는지 확인하고, 누적 이력과 직전 시즌 등 서로 다른 시간 범위와 차이를 피처로 실험했습니다.
**관측된 패턴이 다음 시점에도 유효한지**를 살폈으며, 실험한 피처를 모두 최종 모델에 채택한 것은 아닙니다.

새 피처가 정보를 더하는지, 기존 정보를 다시 표현하는지도 구분했습니다.
FT-Transformer에서는 수치 피처를 의미별 블록으로 묶는 방식과 피처별 토큰화, 모델 깊이를 바꾸어 비교했습니다.
남은 오차를 잔차 모델로 설명하기 어려운 후보는 우선순위를 낮췄습니다.

### 2. 단독 점수와 앙상블 기여를 따로 평가

FTT가 단독으로 가장 좋은 모델이 아닌 비교에서도, 제거하면 전체 성능의 손실이 크게 나타났습니다.
이후 단독 점수뿐 아니라 모델을 **추가·제거·대체**한 결과와 예측의 차이를 함께 확인했습니다.

새 모델을 넣으며 기존 모델의 가중치도 줄인 실험에서는 두 효과가 섞였습니다.
가중 이동과 모델 교체를 나누어 비교했으며, 예측 상관이 낮다는 이유만으로 후보를 채택하지 않았습니다.

### 3. 투수 수준·경기 상황·기록 체계를 학습 구조에 반영

일부 모델에서 투수 간 예측 차이가 평균 쪽으로 압축되어, 투수별 평균 예측과 순위를 따로 진단했습니다.
과거 등급 분포에서 기준 로짓을 만들고, 이력이 적으면 전체 분포 쪽으로 보정했습니다.
**팀원의 FTT를 바탕으로 구성한 margin FTT**에서는 이 기준값에 모델의 조정 로짓을 더해 투수 수준과 상황 효과를 분리해 학습하도록 유도했습니다.

```text
과거 선수 이력 → 표본량을 고려한 기준 로짓
경기 상황·선수 피처 → 모델의 조정 로짓
기준 로짓 + 조정 로짓 → softmax → 3등급 확률
```

같은 컬럼이라도 1군·퓨처스의 반대투구 기록 방식에 따라 결과의 의미가 달랐습니다.
과거 이력을 합치는 기준과 상황별 보정을 학습하는 표본을 구분하고,
1군에 적용할 카운트 보정은 1군 기록으로 다시 적합해 퓨처스 적용 방식과 나누어 평가했습니다.

## 검증에서 드러난 한계

검증의 개선이 제출에서 유지되지 않을 때 모델과 비교 조건을 함께 되짚었습니다.

| 확인한 차이 | 재점검한 내용 |
| --- | --- |
| 학습 연도·시드 수가 다른 기준 모델 | 비교 모델의 학습 조건을 맞추고 반복 실행의 변동 확인 |
| 검증 모델에 맞춘 보정값 | 제출 모델의 출력 수준 변화와 보정 효과를 분리 |
| 모델 교체와 가중 변경을 동시에 수행 | 변경을 나누어 각 효과 비교 |
| 특정 연도에만 나타난 개선 | 여러 시간 구간에서 결과를 확인하고 후보 재평가 |

이 기준은 기존 실험을 돌아보며 수정한 것으로, 새 후보의 제출 성능을 보장하지는 않습니다.
추론에서는 행의 순서·부분집합을 바꿨을 때의 예측 일관성, 확률 범위와 합, 저장·복원 및 제출 환경을 점검했습니다.

본선 모델에는 트리 모델과 팀원들의 보정·결합 로직도 함께 사용했습니다.
